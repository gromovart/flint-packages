# Публичные пакеты Flint

Каталог открытых компонентов для [Flint](https://github.com/gromovart/flint).
Здесь находятся примеры скиллов, ролей субагентов, хуков, workflow и подключений.
Лицензия — [MIT](LICENSE), Artem Gromov. Это отдельный каталог, а не установщик самого Flint.

**Предварительный доступ:** каталог открыт, но основной репозиторий Flint пока закрыт.
Ссылки на ядро, его документацию и установщик доступны только участникам с доступом.
Остальные пользователи смогут пройти полную установку после публичного открытия ядра.
Уже установленный Flint 0.13.2 может получать эти публичные пакеты без входа в GitHub.

## Демонстрационный комплект 1.0.0

Комплект помогает понять подключение компонентов и проверить их на учебном проекте.
Нужны Flint **0.13.2**, Git и `python3` в PATH на macOS или Linux.
Для проверки поведения внутри агента нужен отдельный аккаунт агента.
Сам комплект не использует токены, платные API или сетевые сервисы.

| Часть | ID в Flint | Что делает | Git-тег |
|---|---|---|---|
| Скилл | `flint/demo-skills` | Возвращает маркер `FLINT_DEMO_SKILL`, по запросу проверяет MCP | `demo-skills-v1.0.0` |
| Роль | `flint/demo-subagents` | Описывает рецензента `flint-demo-reviewer` | `demo-subagents-v1.0.0` |
| Хук | `flint/demo-hooks` | Добавляет контекст `FLINT_DEMO_HOOK` при `UserPromptSubmit` | `demo-hooks-v1.0.0` |
| Workflow | `flint/demo-workflows` | Проверяет наличие `AGENTS.md`, затем ждёт человека | `demo-workflows-v1.0.0` |
| MCP | `local/flint-demo-ping` | Инструмент `demo.ping` возвращает `FLINT_DEMO_OK` | `demo-connection-v1.0.0` |

**Важно:** адаптер хуков Flint 0.13.2 поддерживает Codex **0.167.x**, но не 0.169.0.
На 0.169.0 установите хук только в каталог, без активации.
Не меняйте версию агента только ради этого примера.
Нативное обнаружение и вызов роли ещё требуют ручного подтверждения.
Роль включает только вариант Codex. Работа обычного профиля Claude Code сейчас блокируется проверкой инструкций ядра.

Flint 0.13.2 принимает один тип Git-компонента за раз.
Поэтому комплект устанавливается пятью отдельными командами с отдельным согласованием и откатом.
Main этого репозитория содержит каталог и документацию.
**Не устанавливайте main без `--ref`: в его корне нет устанавливаемого пакета.**

## 1. Подготовьте учебный проект

1. Установите Flint по [инструкции](https://github.com/gromovart/flint/blob/main/README.md).
2. Создайте пустую папку проекта на компьютере.
3. Выполните `flint setup`.
4. Создайте личное пространство или выберите своё учебное пространство.
5. Подключите созданную папку и выберите Codex.
6. Завершите настройку по подсказкам.
7. Выполните `flint ls` и запишите короткие имена пространства и проекта.

В командах ниже замените `SPACE` и `PROJECT` этими именами.
Например, `--workspace personal --project demo`.
Не вводите слова в верхнем регистре буквально.
Команды вводятся в обычном терминале. Они работают из любой папки.
Если агент этого проекта открыт, завершите его через `/exit` перед изменением компонентов.

Проверьте доступность необходимых программ:

```sh
flint --version
git --version
python3 --version
```

## 2. Проверьте исходники и установите комплект

Python-код MCP, хука и workflow исполняется с правами пользователя ОС.
Перед согласием изучите [исходники](packages/demo) и план Flint.
Объявленные права не создают файловый или сетевой sandbox.
В текущих исходниках MCP возвращает константу, хук не сохраняет запрос, workflow проверяет только наличие `AGENTS.md`.

Выполните команды по очереди. Подтвердите каждый план отдельно:

```sh
flint package add https://github.com/gromovart/flint-packages.git --ref demo-skills-v1.0.0 --workspace SPACE --project PROJECT --agent codex
flint package add https://github.com/gromovart/flint-packages.git --ref demo-subagents-v1.0.0 --workspace SPACE --project PROJECT --agent codex
flint package add https://github.com/gromovart/flint-packages.git --ref demo-hooks-v1.0.0 --workspace SPACE
flint package add https://github.com/gromovart/flint-packages.git --ref demo-workflows-v1.0.0 --workspace SPACE --project PROJECT
flint package add https://github.com/gromovart/flint-packages.git --ref demo-connection-v1.0.0 --workspace SPACE --project PROJECT --agent codex
```

У хука намеренно отсутствует `--project`: он сохраняется без включения.
У workflow нет `--agent`, поскольку процедуру исполняет Flint.
Все пять установок независимы. При ошибке предыдущие согласованные установки сохраняются.
Повторите только незавершённую команду после устранения причины.

Проверьте установленный состав:

```sh
flint package list --workspace SPACE
flint skill list --workspace SPACE
flint subagent list --workspace SPACE
flint hook list --workspace SPACE
flint workflow list --workspace SPACE
flint connection list --workspace SPACE
```

Должны присутствовать пять строк пакетов из таблицы.
Хук должен оставаться без привязки к проекту на Codex 0.169.0.
Наличие строк подтверждает установку, а не исполнение компонентов.

## 3. Проверьте MCP-подключение

```sh
flint connection check local/flint-demo-ping --workspace SPACE --project PROJECT --agent codex
flint SPACE PROJECT
```

Первая команда проверяет доступность подключения.
Вторая открывает новую сессию агента с установленными компонентами.
В агенте отправьте запрос:

> Вызови MCP-инструмент demo.ping без аргументов и покажи фактический ответ. Не используй терминал и не читай файлы.

Ожидаемый текст результата инструмента: **`FLINT_DEMO_OK`**.
Имя нативного инструмента может содержать сгенерированный префикс Flint.
Ответ модели с маркером без записи о вызове инструмента не подтверждает работу подключения.
Если инструмент отсутствует, завершите старую сессию и откройте новую через Flint.

## 4. Проверьте скилл и роль

Для отдельной проверки обнаружения скилла, без обращения к модели:

```sh
flint skill info flint/demo-skills --workspace SPACE --project PROJECT --agent codex --probe
```

Затем в новой сессии агента попросите:

> Примени скилл flint-demo. Сообщи, какие возможности комплекта доступны фактически. Ничего не изменяй.

Ожидайте применение навыка и маркер `FLINT_DEMO_SKILL`.
Затем отдельно попросите:

> Вызови субагента flint-demo-reviewer для проверки AGENTS.md текущего проекта. Ничего не изменяй. Покажи фактический результат роли.

Ожидаемый маркер роли — `FLINT_DEMO_ROLE`.
Этот сценарий проверяет делегирование только при фактическом вызове субагента.
Если механизм недоступен, запишите результат как неподтверждённый.
Установленный TOML-файл сам по себе не доказывает вызов роли.

## 5. Запустите workflow

Завершите сессию агента. Выполните в терминале:

```sh
flint workflow run flint/demo-workflows --workspace SPACE --project PROJECT
```

После согласия первая проверка ищет `AGENTS.md` в корне проекта.
Она не оценивает качество инструкций и не запускает модель.
При отсутствии файла результат — `FAIL`; сначала завершите настройку правил проекта.
Если файл найден, запуск останавливается в `WAITING_USER`.

Скопируйте ID запуска из результата и замените им `RUN_ID`:

```sh
flint workflow status RUN_ID --workspace SPACE
flint workflow resume RUN_ID --workspace SPACE --decision approve
```

Первая команда показывает проверку `instructions: PASS` и ожидание шага `confirm`.
Вторая фиксирует ваше ручное решение. Ожидайте `COMPLETED` и `MANUAL_APPROVED` у ручного шага.
Это не доказательство успешной проверки всех возможностей комплекта.
Чтобы отменить незавершённый запуск, используйте `flint workflow cancel RUN_ID --workspace SPACE`.
Не выполняйте `approve`, если проверяемый результат вас не устраивает.

## 6. Проверьте хук только на поддержанной версии

На Codex 0.169.0 пропустите этот шаг: активация блокируется.
На уже настроенном Codex 0.167.x можно отдельно включить хук:

```sh
flint package enable flint/demo-hooks --workspace SPACE --project PROJECT --agent codex
flint SPACE PROJECT
```

В новой сессии отправьте обычный запрос и проверьте получение контекста `FLINT_DEMO_HOOK` на событии `UserPromptSubmit`.
Один ответ модели с маркером не заменяет доказательство срабатывания нативного события.
Проверка Python-обработчика в тестах также не доказывает доставку события самим Codex.
Если вы не можете наблюдать событие, отметьте проверку как неподтверждённую.

## 7. Отключите или удалите примеры

Сначала завершите агент и завершите либо отмените ожидающие workflow.
Отключение одной привязки сохраняет пакет в каталоге:

```sh
flint package disable flint/demo-skills --workspace SPACE --project PROJECT --agent codex
```

Для удаления всего комплекта выполните:

```sh
flint package remove local/flint-demo-ping --workspace SPACE
flint package remove flint/demo-workflows --workspace SPACE
flint package remove flint/demo-hooks --workspace SPACE
flint package remove flint/demo-subagents --workspace SPACE
flint package remove flint/demo-skills --workspace SPACE
```

Команды не удаляют исходники учебного проекта.
Каждая изменяющая операция показывает ID транзакции.
Для её отмены используйте `flint package rollback --workspace SPACE --transaction TRANSACTION_ID`.
Откатывайте операции в обратном порядке. Самостоятельно изменённые файлы могут заблокировать откат.

## Устройство каталога

```text
packages/demo/
├── skills/       package.yaml + skills/flint-demo/SKILL.md
├── subagents/    package.yaml + роль и вариант Codex
├── hooks/        package.yaml + hook.yaml + hook.py
├── workflows/   package.yaml + workflow.yaml + scripts/check.py
└── connection/  connection.yaml
sources/
└── mcp_server.py Читаемый исходник встроенного MCP-сервера
scripts/
└── export-tags.py Создание корневых Git-снимков для установки
```

В текущем формате подключения Flint не копирует произвольный `server.py` из Git-репозитория.
Поэтому пример запускает `/usr/bin/env python3 -u -c` со встроенным фиксированным кодом из `connection.yaml`.
Это демонстрационное решение. Для настоящего сервера установите отдельную программу и укажите абсолютный путь.
Тест сверяет встроенный код с читаемым `sources/mcp_server.py`.
Сервер не исполняет команды из запросов, не читает файлы и не обращается к сети.
PATH определяет выбранный `python3`; используйте доверенное окружение терминала.

Одиночное подключение получает версию Flint `0.0.0+local`: формат `ConnectionPackage` пока отсутствует.
Его выпуск различается тегом и закреплённым commit.
Остальные четыре пакета имеют `spec.version: 1.0.0`.

## Проверки для разработчика

```sh
python3 -m unittest discover -s tests -v
```

Для выполнения Git-workflow нужен 0.13.2: в 0.13.1 запуск ошибочно считал Git-источник локальной папкой.

Восемь проверок исполняют синтетические компоненты и проверяют экспорт тегов без Flint, сети и модели.
Если библиотека `harness_core` доступна, дополнительно выполняются шесть интеграционных проверок с временным реестром.
Они проверяют импорт всех типов, совместимые привязки, запрет хука 0.169.0, MCP stdio, ручной workflow, удаление и откат.
В CI без установленного Flint интеграционная группа явно пропускается.
Чтобы проверить её, используйте Python окружения разработки Flint:

```sh
/полный/путь/к/flint/.venv/bin/python -m unittest discover -s tests -v
```

Эти тесты не доказывают нативное обнаружение роли, срабатывание события Codex или исполнение скилла моделью.

## Как добавить свой пакет

1. Создайте папку `packages/your-package` с поддержанным манифестом.
2. Добавьте README с назначением, правами, версиями, установкой и удалением.
3. Добавьте только публичные синтетические данные.
4. Проверьте локальный импорт и реальный Git-тег в учебном пространстве.
5. Откройте Pull Request с описанием результата.

Для новичка проще отдельный репозиторий с одним пакетом в корне.
[Полное руководство автора](https://github.com/gromovart/flint/blob/main/docs/package-authoring.md).
Публикация здесь не делает автора доверенным издателем подписанных правил.

Для выпуска демонстрационного комплекта сопровождающий фиксирует изменения, затем выполняет:

```sh
python3 scripts/export-tags.py --version 1.0.0
```

Скрипт создаёт пять локальных тегов из зафиксированных папок и ничего не отправляет в сеть.
Он отказывается переносить существующие теги и требует чистую рабочую копию.
Перед публикацией проверьте `git show TAG:package.yaml` либо `git show demo-connection-v1.0.0:connection.yaml`.
Отправляйте только перечисленные новые теги. Старые опубликованные теги остаются неизменными.
